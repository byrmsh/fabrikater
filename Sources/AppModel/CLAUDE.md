# AppModel

The app's state and behaviour, as `@MainActor @Observable` stores plus the platform-neutral UI values (`AppCommand`, `Keymap`). Builds and tests on Linux; the views in `AppUI` only read these and call `perform(_:)`.

- `AppStore` is the root: it owns the selection, the sidebar rows and the connection state, applies `HerdUpdate`s, and routes every `AppCommand`. `ConversationStore` holds one window's transcript (with `TranscriptCache`), the main window's selected pane or a `PaneWindowStore`'s pane (decisions/0010), `ComposerStore` sending, with the drafts in `Drafts` (one per app, shared by every window's composer, kept in `UserDefaults` through `DraftStorage`), `PanePanels` each window's inspector and popover, `TerminalStore` each window's terminal view (read only while on screen), `WorkspaceLayout` whether the detail shows the conversation or the terminal, `MenuTarget` which window a menu command reaches, and `FocusSync` moves Herdr's focus to the selection. A window's pane stores (conversation, composer, prompt card, terminal, panels, layout) and the commands that act on them live together in `PaneDetailStores`, which the main window and each pane window own one of, so a pane detail feature is wired once for both. Each store is one file behind the protocol it needs, so a feature can be removed by deleting its file and its line in `AppStore` or `PaneDetailStores`.
- `SendGuard` wraps `HerdrControl` and refuses to type while the pane's screen shows a dialog (`PromptKit`'s `Dialog`); with Claude Code's input box on screen it types only into an empty box and sends Enter only once the box shows the text (`InputBox`). Every keystroke it sends carries a `ScreenCheck` the host runs right before it (decisions/0012). Escape and Control-C alone skip the dialog check, so the key bar (`PaneKey`) can back out of a dialog. The composition root puts it inside `PolicedControl`.
- `ScreenWait` is the one 8 × 350 ms wait for a pane's screen to show what was just sent, and `Pause` the injectable sleep every polling store takes.
- `PromptCardStore` (one per window, like the composer) reads a `blocked` Claude pane's screen into a `PromptCard` and answers it: a fresh read must show the same `Prompt`, and the keys go as one `.checked` request bound to the prompt's rows. Its control is the composition root's `PolicedControl` without `SendGuard`, which would refuse the digits (decisions/0013).
- Stores never build services. Their initializers take protocols (`TranscriptService`, `HerdrControl`) or streams (`AsyncStream<HerdUpdate>`); the composition root in `fabrikater` passes the real ones, tests pass fakes.
- A view never decides, formats or falls back: labels, header text, status words and empty-state messages are store properties, tested here (`.claude/skills/macos-design`, Rule 1).
- Input methods change state synchronously, then start host work in a `Task`. When a read fails, keep the last data and say it is stale.
- A new user action is a new `AppCommand` case with its title, handled in `AppStore.perform(_:)` (or, for a command on a window's pane, listed in `PaneDetailStores.handles(_:)`, which `AppStore` and `MenuTarget` route by), and a `Keymap` entry if it has a shortcut.
- `ConversationFind` is the find bar (⌘F) over a window's conversation: the matching entries, the current one and the count. `ConversationStore` holds one and re-searches whenever its transcript changes; the views highlight with its `ranges(of:in:)`. Removing find means deleting the file, its commands and `AppUI`'s `FindBar`, `FindHighlight` and `FindCommands`.
- `MarkdownBlock.parse` splits a message into the blocks `AppUI`'s `MarkdownView` lays out (decisions/0011); inline styling stays in each block's text. `Highlighting/` colours code blocks and diff lines: `CodeLanguage` names a language from a fence word or a file extension, each language is a `LexRules` value (or, for diff, a tokenizer) in its own file, and `CodePalette` holds the light and dark colours, tested for contrast. A language is added with one file and one case.
- `PastSessions.swift` (M8) holds the Past Sessions sheet (`PastSessionsStore`, listing through `TranscriptKit`'s `SessionHistory`) and a past session's window (`SessionWindowStore`, opened with a `SessionWindowID`); its `ConversationStore` shows a log with no pane behind it (`show(_: SessionLog)`).
- `NeedsYou` (the sidebar's first group, ⌘1…⌘9 and the Dock badge) is derived from the finished `sections`, not part of them, so navigation ignores it. `PaneAlerts.swift` decides which herd changes notify and posts them through `Notifier`; the composition root passes the system's notification centre.
- `HostSession` holds the `AppStore` of the host connected to now. The composition root gives it one closure that builds a host's services and store; connecting to another host (`PreferencesStore.connect()`) calls `AppStore.close()`, which stops the herd feed, every log follow, terminal read and focus move and closes the host's pane and past-session windows, then builds the next store. Anything that reads the host from a task must stop in `close()`: a store with a task adds its own `close()` and `PaneDetailStores.close()` or `AppStore.close()` calls it. Preferences, drafts and pane notes live in `UserDefaults`, so they outlive the store.
- `Preferences` (the Settings window's values: host, send key, notification kinds and sound, text sizes) live in `PreferencesStore` behind `PreferencesStorage`; `AppStore` holds it and filters notifications by it, and the views read the send key and text sizes from it.
- Per-pane local state (names, pins, unread marks, hidden panes, muted workspaces) lives in `PaneNotes` behind `PaneNotesStore`; a feature adds only its own field. Sidebar features are pure functions in `Sidebar+<Feature>.swift`, applied one per line in `AppStore.refreshSections()`; one that sets a per-pane value goes through `mappingPanes(_:)` rather than walking sections and tabs itself.
